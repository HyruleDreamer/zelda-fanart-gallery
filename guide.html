The keeper's guide

Your art.
Your stories. Simply shared.

Everything lives in your GitHub repository. There are no subscriptions, accounts for visitors, or upload services to manage.

This is a static website: it displays files but cannot save uploads. Use GitHub’s built-in Add file → Upload files tool to add your illustrations.

1. Add your first illustration

  1. Open your repository. Choose the branch you are working on.
  2. Open images/silent-world/ (or the folder for your story). Choose Add file → Upload files. Upload your original, for example moonlit-reunion.png, then save the change.
  3. Make a smaller copy of the image, about 600–900 pixels wide. Upload it to thumbnails/silent-world/, for example moonlit-reunion.webp. This keeps the gallery fast. If you omit a thumbnail, a CSS preview will appear; the original still opens in the viewer.
  4. Open data/gallery.js and click the pencil to edit. Replace the hidden example with your real entry, following the sample below. Remove example: true only after uploading the original. Save the change.
{
  id: "moonlit-reunion",
  story: "silent-world",
  title: "Moonlit reunion",
  chapter: 1,
  description: "A quiet reunion beneath the moon.",
  alt: "Describe what is actually shown in your image.",
  filename: "moonlit-reunion.png",
  thumbnail: "moonlit-reunion.webp"
}

This sample is instructional, not an existing illustration. Spell filenames exactly, including capital letters. Use simple lowercase names with hyphens. Use PNG, JPG, WebP, GIF, or AVIF. Put a comma between entries. Keep image files below GitHub’s browser upload limit (25 MiB); much smaller files are better for readers. Chapter, description, and thumbnail are optional. Give every illustration useful alt text for people who cannot see it.

2. Preview before publishing

Download the review branch using GitHub’s Code → Download ZIP, extract the ZIP, then double-click index.html. Search, filters, and the viewer run directly from the folder. If automatic clipboard access is unavailable, a text box lets you copy manually. The hidden example will not create a broken image.

3. Publish with GitHub Pages

After reviewing and approving the changes, merge them into main. Open the repository’s Settings → Pages. Under Build and deployment, choose Deploy from a branch, choose main and / (root), and click Save. Wait until GitHub reports that your site is live.

Your website address will be https://HyruleDreamer.github.io/zelda-fanart-gallery/. That address will only work after publication. Future saved changes on the publishing branch appear after GitHub finishes deploying them.

4. Place an image in AO3

  1. Visit the published gallery and open your illustration.
  2. Choose Copy AO3 HTML.
  3. In your AO3 chapter editor, switch to HTML, paste the copied code where you want the image, and preview the chapter.
<img src="https://HyruleDreamer.github.io/zelda-fanart-gallery/images/silent-world/moonlit-reunion.png" alt="Your image description">

The copy buttons always use the final GitHub Pages address, including during local preview. Links will not load until the original image is uploaded and deployed. Test a copied URL in a browser before posting. For phone-friendly images, optionally add style="max-width:100%;height:auto;" to the image element, then preview it in AO3.

Keep your links lasting

Once you embed an image, keep its filename, story folder, repository name, and GitHub username unchanged. Moving, deleting, or renaming any of these can break links in old chapters. To replace an image while preserving its URL, upload a new version with the same filename. GitHub may take a little time to refresh it.

Add another story

Add a new entry to the stories list in data/gallery.js, with a unique lowercase id and a title. Use that exact id for its image folder, thumbnail folder, and illustration entries. Navigation updates automatically.

A note about privacy

Use HyruleDreamer for public credits and your confirmed GitHub noreply address for commits. Check your GitHub email privacy settings before saving changes. Remove personal details and location information from image metadata before uploading. Images in this public repository and website can be viewed and downloaded by anyone.
